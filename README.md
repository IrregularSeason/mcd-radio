# 麦门电台 · FM 1024

> 一档**只为你一个人播**的麦当劳电台。

打开它，它用麦当劳当天的真实数据给你播一期节目 —— 今天的活动还有几天结束、
哪张券今晚就作废、你有多少积分已经默默过期、你想吃的那份现在多少钱。
然后把它合成一段能直接发出去的音频。

**▶ 想听一期**：克隆后在本机跑一条命令，它就用**当天**的数据给你生成一期。产物是
`card.html`（内嵌播放器，打开即听）、`episode.m4a` 和 `script.md`。

```bash
python3 scripts/broadcast.py --out-dir episodes/today --point 中薯条 \
    --city 深圳 --keyword 万象城
```

> **为什么不把音频放进仓库**：每期节目是一次性的，而且它**含当期券包、积分与门店的真实快照**。
> 所以这个项目的交付物是「**生成能力**」，不是「某一期成品」——
> 同一条命令，明天播出的内容完全不同。

---

## 一期节目长这样

以午间档为例，六段的结构是这样的。下列为**结构示意**——尖括号是数据填充位，
数值仅用于演示排版，**不取自任何真实账号**：

> **麦门电台，FM 1024。午间点播，第 N 期。**
> 现在是 X 月 X 日，周 X，XX 点 XX 分。
>
> **【今日现场】** 先说今天的事。⟨最快结束的那场活动⟩，还有 N 天结束。
> 另外，下一场联名开售也已经定好时间了：⟨活动名⟩，X 月 X 日 XX 点 XX 分开售。
>
> **【听众信箱】** 你的卡包里现在有 N 张券，能用的 M 张。最急的一张是
> 「⟨券名⟩」，X 月 X 日到期，还有 N 天。你的积分账户里，已经有 N 分过期了 ——
> 系统不会通知你这件事，所以你一直不知道。
>
> **【点播时间】** 有听众点了一份⟨餐品⟩。核过价了，不用券的实付是 X 块 X。
> 在⟨门店名⟩，现在下单就能取。你的卡包里正好有一张「⟨券名⟩」，可能用得上。
>
> **【今日代号】**「⟨从当天活动文案里挑出的一个词⟩」。这个暗号按日期算出来，不是抽的。
>
> **【收尾】** ⟨按时段分别取句——午间不会说「晚安」⟩

真实播出时，上面每一个填充位都来自麦当劳 MCP 的实时返回。**某项数据取不到时，
整段直接不播，而不是编一句填上。**

## 为什么做电台

因为**没有人做**。

本届大赛共 **583 个参赛项目**（截至 2026-10-14 的统计口径）。我用官方 API 逐个统计了各主题的密度：

| 主题 | 项目数 |
|---|---:|
| 早餐 | 39 |
| 优惠券（标题含「券」） | 37 |
| 积分 | 27 |
| 最佳方案/最优解 | 20 |
| 情绪 | 16 |
| 心情 | 13 |
| 音乐 | **1** |
| 播客 | **1** |
| **电台** | **0** |

声音形态是一片空地。而且不只是空 —— 那 1 个提到「播客」和 1 个提到「音乐」的项目，
都只是在功能列表里顺带提了一句，没有一个把声音当成产品本身。

**顺带一个更有意思的对比**：「情绪」被 16 个项目占用，「心情」13 个，
但**所有具体的情绪场景都是 0** —— 治愈 0、孤独 0、许愿 0、情书 0、塔罗 0、助眠 0。
大家做的其实是同一件事：识别情绪 → 推荐一份餐。

而这个项目做的是另一件事：**把真实数据变成一段有声音的陪伴。**

## 六段结构

电台不是「AI 陪你聊天」。它有固定的节目结构，每段都由真实数据驱动：

| 段落 | 数据来源 | 它提供什么 |
|---|---|---|
| **台标与报时** | `now-time-info` | 台名、频率、期号、服务器时间 |
| **今日现场** | `campaign-calendar` | 最快结束的一场活动 + 下一场联名开售倒计时 |
| **听众信箱** | `query-my-coupons`、`query-my-account` | 最急的一张券、积分临期或已过期 |
| **点播时间** | 四步核价链 | 听众点的那份餐，真实门店、真实价格 |
| **今日代号** | `campaign-calendar` | 当天出现过的词，按日期确定性选一个 |
| **收尾** | 本地文案库 | 按时段（早/午/晚）分别取句 |

**节目名和主播音色按时段自动切换**：早间《麦门晨报》、午间《午间点播》、深夜《麦门夜话》。

## 三个实测撞出来的坑

这个项目不只是「调用接口 + 念出来」。开发过程中有三个坑，都写在
[`SKILL.md`](SKILL.md) 里，也是这个项目技术含量的证明：

### 1. TTS 的静默失败：会「成功」地生成一期无声节目

`say -v Reed` 不报错、返回成功、写出一个结构完全合法的音频文件 ——
**但内容是 0.016 秒的空白**。只有带语区的完整名 `Reed (中文（中国大陆）)` 才真正合成。

所以 `speak.py` 里有一道**时长自检**：合成完读一遍音频长度，短于预期下限就
换音色重试。`say` 的退出码对这个错误完全无感，只能靠量出来的时长判断。

### 2. `query-meals` 只给编码，不给名称

想按「中薯条」找商品，只能逐个调 `query-meal-detail`。一家门店的菜单有
**118 个编码** —— 也就是说按名字找一份餐，真实成本是几十到上百次调用。
项目把结果按门店缓存下来，只有首期慢，之后几秒就能找到。

### 3. 官方文案里的「𝟗.𝟗」不是普通数字

活动标题用数学粗体数字做视觉强调（U+1D7CE–U+1D7FF）。按 emoji 一并删掉的话，
「超值𝟗.𝟗元早餐两件套」会变成「**超值.元早餐两件套**」—— 价格当场消失，
而朗读时会念成一句不通的话。要按码位映射回普通数字，再清表情符号。

另外两个语气层面的坑：收尾语必须按时段分组（第一版在中午 14 点的节目里
说了「晚安」）；联名标题里的「麦当劳 X PEACEMINUSONE」要转成「麦当劳与……」，
否则会被念成字母 X。

## 安装

### 1. 拿到麦当劳 MCP Token

前往 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp) 手机号登录 → 控制台 → 激活。

### 2. 配置 MCP 连接器

在 WorkBuddy 里：左侧【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→
填入 [`mcp-config.example.json`](mcp-config.example.json) 的内容，把
`${MCD_MCP_TOKEN}` 换成你自己的 Token。**真实 Token 不要提交进任何仓库。**

### 3. 安装本 Skill

```bash
git clone https://github.com/IrregularSeason/mcd-radio.git
mkdir -p ~/.workbuddy/skills
cp -r mcd-radio ~/.workbuddy/skills/mcd-radio
```

### 4. 播一期

在 WorkBuddy 里直接说人话：

```
播一期麦门电台
今天有什么值得听的
我想点一份中薯条，帮我播一期
```

或者用命令行一次跑完：

```bash
python3 scripts/broadcast.py --out-dir episodes/2026-10-15 --point 中薯条 \
    --city 深圳 --keyword 万象城
```

## 离线演示（不需要 Token）

`fixtures/` 里放着脱敏后的实测响应，任何人都能复现一期节目：

```bash
python3 scripts/broadcast.py --offline --out-dir demo
```

**这个演示是可验证的**：离线复现出的文稿与实时播出的那一期**逐字一致**，
唯一差异是时间戳（因为样本的抓取时刻与播出时刻不同）。也就是说，
文稿确实只由数据决定，没有被模型即兴发挥过。

## 工程约定

- **纯 Python 标准库**，零第三方依赖。唯一系统依赖是 TTS（macOS 自带 `say`）。
- **写稿与取数分离**：`station.py` 不做任何网络请求。因此文稿可离线测试、
  可复现、可 diff —— 这是它能保证「每天质量稳定」的原因。
- **绝不编造**：每个数字都必须能在 MCP 返回里找到出处。某一项数据缺失时，
  整段不播，而不是编一句话填上。
- **只读**：不领券、不下单、不抽奖、不兑换。电台不替听众做决定。

## 目录结构

```
mcd-radio/
├── SKILL.md                    # 编排指令：调用链、节目结构、实测坑清单
├── README.md
├── MCP_INTEGRATION.md          # MCP 接入说明：工具、流程、业务价值
├── mcp-config.example.json     # 配置模板（仅环境变量占位符）
├── CONTEST_DECLARATION.md      # 参赛声明（官方原文）
├── scripts/
│   ├── broadcast.py            # 一键播出：取数 → 写稿 → 合成
│   ├── station.py              # 文稿生成内核（离线，不发网络请求）
│   ├── speak.py                # TTS 合成 + 时长自检 + 转码
│   ├── probe_mcp.py            # MCP 探针（列工具 / 导 schema / 调工具）
│   └── sanitize_fixtures.py    # 实测样本脱敏 + 泄漏自检
├── fixtures/                   # 脱敏后的实测响应（离线演示用）
└── episodes/                   # 每期节目产物（本机生成，已在 .gitignore 中）
```

`episodes/` 里会出现当期券包、积分与门店的快照，属于个人数据，因此不随仓库分发。
任何人都能用 `fixtures/` 里的脱敏样本在本地复现一期。

## 合规

- 仓库内**不包含任何真实 Token、密钥或账号凭证**。`fixtures/` 经脱敏工具处理，
  并做了幂等性与泄漏自检。
- 仓库内**不包含任何一期真实节目的产物**。`episodes/` 已在 `.gitignore` 中——
  节目正文会出现当期券包、积分与门店信息，属个人数据，不随仓库分发。
- Token 只从环境变量或本机连接器配置读取，不落盘、不入库。
- 本项目为参赛者独立开发的参赛作品，**非麦当劳官方产品**，不构成对麦当劳及其
  关联方商标的任何授权或背书。
- 所有餐品、价格、券、积分与活动信息均来自麦当劳 MCP 实时返回，以官方渠道为准。
